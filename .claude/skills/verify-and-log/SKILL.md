# إجراء ما بعد التعديل: اختبار ومعاينة وتصحيح وتسجيل

نفّذ هذه الحلقة كاملةً بعد أي تعديل على الكود، وقبل اعتبار المهمة منتهية.

## 1) الاختبار

- فحص الأنواع و ESLint على نطاق التغيير:
  - `npx tsc --noEmit`
  - `npm run lint`
- قبل إنهاء المهمة (وقبل أي نشر): البناء الكامل `npm run build`. **لا تُسلّم عملاً والبناء فاشل.**

## 2) المعاينة البصرية على الجوال (إلزامي)

- شغّل الموقع محلياً: `npm run dev`.
- عبر خادم Playwright (MCP باسم `playwright`)، افتح **الصفحات المتأثرة فقط** على ثلاثة مقاسات:
  - **iPhone**: اضبط المقاس على ~390×844 (`browser_resize`)، ثم `browser_navigate` فـ `browser_take_screenshot`.
  - **Android**: اضبط المقاس على ~412×915، وكرّر.
  - **سطح المكتب**: ~1280×800.
- في كل مقاس تحقّق من:
  - لا تمرير أفقي ولا نص مقطوع ولا عناصر متداخلة.
  - اتجاه RTL سليم، والنصوص مقروءة دون تكبير، وأهداف اللمس كافية.
  - أخطاء الـ console عبر `browser_console_messages` — خصوصاً أخطاء WebGL/الحركة على iOS (راجع `CRITICAL_IOS_CRASH_FIX.md`).
- عايِن في الوضعين العربي (rtl) والإنجليزي.

## 3) إصلاح الأخطاء

- صحّح أي خطأ ظهر في الخطوتين 1 و2، ثم كرّر (1 → 2 → 3) حتى تخلو كل المقاسات من الأخطاء.

## 4) تسجيل الملفات المعدّلة

- يوجد hook يسجّل كل ملف معدّل تلقائياً في `.claude/CHANGES.md`.
- نسخة احتياطية إن لم يعمل الـ hook (مثلاً Windows دون Git Bash): أضِف يدوياً سطراً لكل ملف بالصيغة:

  ```
  - 2026-06-08 14:30 — `المسار/إلى/الملف`
  ```

- في نهاية المهمة، أضِف سطر ملخّص واحد يصف التغيير ونتيجة الاختبار، مثل:

  ```
  > تعديل التذييل ليقرأ بيانات الاتصال من CMS — البناء ناجح، عوينت / و /contact على iPhone و Android بلا أخطاء.
  ```
